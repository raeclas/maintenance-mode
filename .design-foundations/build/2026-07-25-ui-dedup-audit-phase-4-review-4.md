## The central check: did the property-enumerated sweep actually hold?

Verified by independently re-walking every cited range in `style.css` and cross-referencing against `index.html`/`main.js` for which selectors actually render together. The sweep's methodology (walk every declaration inside every cited range, grouped by CSS property) is sound and its round-3 self-correction (catching `margin-top` after rounds 1–2 missed it) is real — but re-running the same method surfaces a further miss, in a different place than the value-shape or property-name blind spots the document already caught:

**Finding — the sweep never checked what happens when two cited selectors combine on the same live element.** The Meter spec's own citation for the Level species is `.barTrack`/`.barFill`, **`.popTrack` override** (`style.css:258-259, 309`) — and `index.html:92` is the *only* place `.barTrack` ever renders: `<div class="barTrack popTrack">`. `.popTrack` itself carries a second rule the sweep never opened — `.popTrack { margin: 6px 0 10px; }` (`style.css:308`, one line before the cited `309`). Because `.popTrack` is declared *after* `.barTrack` in file order and both are single-class selectors (equal specificity), the shorthand at 308 overrides `.barTrack`'s `margin-top: 4px` (258) on the one element that actually has both classes. **The token the component tier names — `--meter-level-margin: var(--space-3)` (4px), commented "`.barTrack { margin-top: 4px }`" — is not the value that renders.** The real, always-applying margin on the game's only Level-meter instance is `margin-top: 6px` / `margin-bottom: 10px` / `margin-left/right: 0`, and none of those three values were tokenized, swept, or named as an exception anywhere in the document. This falsifies the round-3 sweep's own closing claim ("nothing else in the table above was left unresolved") on the document's own terms, the same way round 2 falsified round 1's.

Two smaller misses in the same property-enumerated table, both structurally the same failure mode:
- The `width` row lists only `.allocMini input`'s `44px` — it omits `.rowFill`'s `width: 0` (`style.css:300`, inside Meter/Cycle's own cited `299-300`) and `.barFill`'s `width: 0` (`style.css:259`, inside Meter/Level's own cited `258-259`). Zero is almost certainly exempt by the same logic the table already applies to `margin: 0 auto` and `min-width: 0` — but the table doesn't say so; it simply doesn't list them.
- `left: 0; right: 0; bottom: 0;` on `.rowBar` (`style.css:299`, cited by both Row and Meter/Cycle) is a positioning-offset property class the table never names as a category at all, unlike `margin`/`padding`/`gap`/`border`/`width`/`height`, which each get their own row.

None of these three are visually dramatic (the practical delta is a few px of vertical rhythm on one bar, and two zero-length values), but the task's own standard is explicit: a single unswept/unnamed length-carrying value inside a cited range falsifies the exhaustiveness claim, and here there are three, one of which also makes a *stated* token value factually wrong for the element it claims to describe.

## Requirement Fulfillment

### DW-4.1
PREMISE: "Token tiers defined (primitive → semantic → component); every component spec references semantic tokens, never raw values. This covers DIMENSION values (spacing, padding, grid columns, track heights, margins) as well as color — a spec whose px values have no tier backing fails this item. A genuine one-off named honestly as an exception is acceptable; a value silently left untokenized is not."
EVIDENCE: Primitive (`--space-1`…`--space-8`, `--border-hairline`) → component tier (`--row-pad`, `--alloc-gap`, `--meter-track-*`, etc.) is real and the great majority of cited declarations do resolve correctly (verified `--arena-pad`, `--row-pad`, `--alloc-pad`, `--alloc-input-pad`, `--chip-pad`, `--chip-group-pad`, `--arena-margin`, `--arena-controls-margin` all decompose correctly against their cited `style.css` lines). However, the central-check re-sweep found a length-carrying value inside a cited range that is genuinely untokenized and unnamed as an exception: `.popTrack`'s `margin: 6px 0 10px` (`style.css:308`), which is the value that actually renders on the Level meter's one live instance, overriding the `4px` the component tier does tokenize. Two further zero-length gaps (`.rowFill`/`.barFill` `width: 0`; `.rowBar`'s `left/right/bottom: 0`) compound the same completeness gap at lower stakes.
VERDICT: FAIL

### DW-4.2
PREMISE: "A spec exists for each repeated shape: row, rowlist, chip/KPI, meter, arena, allocation control, caption, tab button."
EVIDENCE: All eight named shapes have their own subsection in the Component specs. Each traces to markup that actually renders: Row → `.rowlist .row` built at `main.js:317-328` (training), `344-354` (zones), `465-469` (Delve tree), `479-497`/`501-504` (Dungeon); Rowlist → `.rowlist` (`style.css:262`); Chip/KPI → `#resbar`/`#powerBreakdown` (`index.html:11-33, 125-129`); Meter → four species traced to `battle.js:124-141`, `style.css:299-300/408-410/258-259,309`, cross-checked against `main.js` render calls; Arena → `.arena` at both `index.html:63-70` and `185-196` (verified: Boss tab hosts `<canvas id="battle">`, Dungeon tab reuses the class for a plain control cluster, confirmed by reading `index.html` directly); Allocation control → `allocMini()` (`main.js:288-310`) plus the Dungeon duty-row hand-rolled variant (`main.js:479-497`, confirmed by reading the cited lines); `.caption` → applied to exactly `#cooldown`/`#projection`/`#record`/`#instProject` (confirmed against `index.html`); Tab button → `#tabs button` (`style.css:158-171`, `main.js:224-234`).
VERDICT: PASS

### DW-4.3
PREMISE: "Each component spec states its interaction states including locked and disabled."
EVIDENCE: Row's States table names locked (`.row.locked`, opacity + text-label channel, `style.css:298`) and disabled ("N/A as a distinct visual state... a row is either normal or `.locked`" — an explicit, reasoned absence, not a silent gap). Meter's States table names "locked (inherited)" for Cycle and explicitly reasons why Progress/Level/Depletion have no lockable parent. Allocation control's States table has explicit `locked`/`disabled` rows for both `.allocMini` and the Dungeon duty variant, correctly citing `bots.js:116-122` and `main.js:484-488`/`991` as the gap (verified against source: `setAlloc` at `bots.js:116-122` applies `Math.min(n, ...)` with no lock check; `setParty` at `main.js:484-488` checks only `state.instance.running`, never `dutyUnlocked`; `main.js:991` does gate the sibling `<input>`'s `.disabled` on `!open` — all three claims confirmed true against source). Tab button's States table names locked and explicitly reasons about the disabled gap (focusable-but-inert, flagged not fixed). Chip/KPI, Arena, `.caption`, Rowlist each state "no locked/disabled state exists" with a stated reason (pure readout, layout wrapper, pure text) rather than omitting the topic.
VERDICT: PASS

### DW-4.4
PREMISE: "Meter encoding is consistent — bar length means one thing across training, zones, boss health and dungeon progress, or the differences are explicitly distinguished by form."
EVIDENCE: The Meter spec table names four species (Depletion/Cycle/Progress/Level) and traces each to a distinct combination of medium (canvas vs. DOM), track color/visibility (transparent / `--line-soft` / `--field` / `--field`), and track height (`--space-1`/`--space-2`/`--space-5`/canvas-relative) — all four values confirmed against the cited `style.css` lines. Training and Grind zones both correctly use the *same* species (Cycle, a repeating per-work-unit pulse), which the document explains is correct, not a conflation, since both are literally the same semantic thing (a unit-of-work cycle). Dungeon is confirmed via source (`main.js:966-1006`, `renderInstance()`) to render floor/haul/damage-% as text with a `.warn`/`.sat` color swap, not a bar — matching the claim "Dungeon has none" exactly. The `data-viz` attribute proposed to make the distinction explicit is confirmed absent from shipped code today (grepped `index.html`/`main.js`/`style.css`/`battle.js`/`farm.js`/`bots.js`/`instance.js`/`dungeon.js` for `data-viz`, zero hits) and is correctly labeled REQUIRED, not asserted as shipped.
VERDICT: PASS
